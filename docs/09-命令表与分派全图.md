## 1. 静态命令表：`.data 0x35020`

## 3. 结论：`k=6 / k=7 / k=19` 是"登记但未实现"

这三条在命令表里（`flag=1`，启用），掩码 `0x907` 也放行（6、7 在 0..11 内），但 `.tvm0` 里**没有任何比较点**。

含义很明确：

- 客户端发 `0x63AE4433` / `0x63AE4434` → 通过 token 校验 → 落到链尾默认分支 → 不会有对应动作；
- 这三条是**预留命令位**（版本演进时占坑），或需要另一条未随本次发布下发的密钥才能激活。

这一条把 `docs/08 §9.2` 的"k=6/7 未知"关闭了：不是没找到，是**确实没实现**。

## 4. 状态位图 `0x35B28`：写入者找到了

| 站点 | 指令 | 含义 |
|---|---|---|
| `0x062A10` | `lock or qword ptr [0x35B28], 4` | 置 **bit 2** |
| `0x062BAD` | `lock or qword ptr [0x35B28], 8` | 置 **bit 3** |
| `0x062ED6` | `movzx eax, byte ptr [0x35B28]` | k=5 读 bit 1 |
| `0x063098` | `mov rax, qword ptr [0x35B28]` | 读全 64 位 |
| `0x063327` | `mov eax, dword ptr [0x35B28]` | 读低 32 位 |
| `0x0640A8` | `mov rax, qword ptr [0x35B28]` | 读全 64 位 |

**位图语义**：每条命令执行时用 `lock or` 把自己那一位"点亮"，即**已消费标记**表。所以：

- `0x062A10` 的 `or 4` 落在 k=10 的分支里（`0x62955` 之后）；
- `0x062BAD` 的 `or 8` 落在 k=4 的分支里（`0x62B2F` 之后）；
- k=4 的判定读 bit 3、k=5 的判定读 bit 1 —— 即"这条命令是否已被处理过"的自检。

这解释了为什么 arm 里既有读又有写：**读是为了判断状态，写是为了登记状态**。

## 5. 提交端 `0x6392E` 的真实身份

追踪结果（89 条指令、7 条边）：

```
0x6398D  call 0xC2F0      ; 取上下文/校验请求体
0x639AD  test eax,eax
0x639AF  jne  0x63A60     ; 失败 → 直接返回
0x639BB  mov  eax,[rbx]   ; ← token
0x639BD  add  eax,0x9C51BBD3
0x639C2  cmp  eax,0xB
0x639E0  ja   0x63A1D
0x639EC  mov  ecx,0xFFFFF6F8 / not → 0x907
0x639F3  bt   ecx,eax
0x63A11  jb   return_0
0x63A1D  call 0x2060      ; 读 dat_35008
0x63A24  je   return_0
0x63A30  mov  eax,~0xFFFFFFCF → 0x30
```

所以 `0x6392E` **不是**提交端，它是**准入门（token 校验 + armed 检查）**。真正的执行体在 `0x625B1`（回包构造）之前的调用序列里，即：

```
解码载荷 → sub_5C40(0x6C76E) 解析上下文 → sub_3000(0x6392E) 准入
        → KeWaitForSingleObject(事件) → sub_2950(0x625B1) 组装回包 → KeSetEvent
```

`KeWaitForSingleObject` 说明：**准入通过后由另一个执行体完成动作并置事件**，`0x625B1` 只负责读状态、填 `{0x01343BEB, 0x30, status}`。

## 6. `dat_35008`（armed）的一个细节

文件里 `0x35008 = 1`，但静态扫描（`.text` 全域）**没有找到任何写入者**，只有 `sub_2060` 一处读取。

推论：该值由 `.tvm0` 用**计算地址**写入（TVM 混淆后不使用 rip 相对寻址），也就是"armed 的开关掌握在保护段手里"。这与 `g_KillSwitch(0x35650)` 形成两级控制：

| 标志 | 写入者 | 效果 |
|---|---|---|
| `0x35650` | `.text`（`sub_1680`/`sub_1700` 路径可达） | 关掉 CREATE + IOCTL |
| `0x35008` | `.tvm0`（推断） | 放行后仍可拒绝执行（返回 `0x30`） |
