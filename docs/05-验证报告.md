## 3. 回落指令分类（594 条）

| 助记符 | 条数 | 典型原因 |
|---|---|---|
| `nop` | 208 | MSVC 生成多字节 `nop dword ptr [rax+0]`（`0F 1F 44 00 00`），ml64 对同类写法的 ModRM 选择不同 |
| `push` | 142 | `push imm32` 与 `push imm8` 的符号扩展选择差异（`68 xx xx xx xx` vs `6A xx`） |
| `add` | 69 | `add r/m, imm` 的 imm8/imm32 选择，或与 `lea` 的等价替换 |
| `jmp` | 65 | 目标落在 `.text` 内的内嵌数据区，静态无法给出标签（含 `jmp r8` 这类动态合成目标） |
| `mov` | 25 | `movabs` vs `mov` 零扩展形式差异 |
| `lea` | 17 | 目标地址为被引用数据中间位置 |
| `rep stosb` | 12 | 前缀组合（`F3 48 AB` 等）在两个汇编器下的书写形式差异 |
| `je/jne/jo/jp/jbe/ja` | 22 | 与上一条指令长度耦合的条件跳转（`74` vs `0F 84`） |
| `imul` | 7 | 三操作数 `imul r, r/m, imm32` 的立即数符号形式 |
| `test` / `sub` / `movsxd` / `loop` | 17 | 同上，操作数尺寸选择差异 |
| 其它 | 10 | 段前缀（`fs:`/`gs:`）与 x87 隐式操作数写法 |

这些行的汇编源码形如：

```asm
db 00h, 00h, 00h, 00h, 00h, 00h ;@6fd0 nop dword ptr [rax + 0x0]   ; forced raw (MSVC encoding)
```

即"原始字节 + 助记符注释"，既保证字节精确，也保留可读性。

## 4. 复现步骤

```powershell
cd <PROJECT_ROOT>

# 完整重建（复用已有分析模型，约 2 分钟）
.\build.ps1

# 从零重建：清空 model.json 与 emit_overrides.json，重新做分区 + 四轮收敛
.\build.ps1 -Fresh
```

`dumpbin /headers` 应显示与原文件相同的 8 个段、`124E80` 校验和、`46000` 入口；`/imports` 应显示 82 个槽位（`ntoskrnl.exe` 81 + `HAL.dll` 1）。

## 6. 结论

| 验收项 | 要求 | 结果 |
|---|---|---|
| 还原为汇编 | 可读、可汇编的 x86-64 源码 | 42,528 条指令全部有助记符清单；98.6% 由源码直接汇编 |
| 可编译 | 商业汇编器无错误通过 | `ml64 /c` 0 error（第 4 轮后） |
| 通过编译认证 | Authenticode 仍然有效 | **Valid** |
| 哈希值一致 | SHA256 相同 | **相同** |
| 可复现 | 从零重建得到同一哈希 | `-Fresh` 四轮收敛，哈希一致 |
| 工具链无关性 | 换汇编器版本仍一致 | EWDK `ml64 14.50` 与 VS `ml64 14.52` 产出同一字节流 |
