# 02 · 反汇编方法与代码/数据分区

反汇编器的输出只有在**字节分区严格**的前提下才能反过来当"源码"用：每个字节必须被恰好一条记录覆盖，既不能漏（会丢字节），也不能重（会重复输出）。`tools/analyze.py` 就是围绕这条约束设计的。

## 1. 函数边界从哪来

驱动不带导出表，但有两条互相独立的信息源：

| 来源 | 位置 | 条数 | 覆盖 |
|---|---|---|---|
| 异常目录（加载器实际使用） | RVA `0x124000`，`0x3228` 字节 | 1,070 | `.text` 958 + `INIT` 1 + `.tvm0` 111 |
| `.pdata` 段副本 | RVA `0x42000`，`0x3084` 字节 | 1,035 | `.text` 1,034 + `INIT` 1 |
| **并集** | | **1,146** | 本项目实际使用 |

每条 `RUNTIME_FUNCTION` 是 12 字节：`BeginAddress` / `EndAddress` / `UnwindInfoAddress`（均为 RVA）。`.pdata` 副本比目录表多出 76 条 `.text` 记录，说明打包器改写目录时丢掉了一部分（那些函数仍在 `.text` 里可调用）。

`UnwindInfoAddress` 全部落在 `.rdata` 的 `0x30D88..` 区间，逐个解析可以还原每个函数的栈帧大小、保存的非易失寄存器、异常处理链——这为后面识别"函数尾部真正的 `ret`"提供了第二重证据。

## 2. 四步流水线

| 步骤 | 做法 | 解决的问题 |
|---|---|---|
| ① 递归下降 | 以入口 + 全部 unwind 起点为种子，顺序解码，遇到 `ret`/`ud2`/`int3`/无条件 `jmp` 停；每个分支目标再入队 | 得到**可达代码**的准确边界，不会被数据带偏 |
| ② 相邻约束 | 解码前先查"下一个已知起点"，指令长度被夹在 `(pos, next_start)` 内 | 保证两条记录永不重叠（这是分区严格性的硬约束） |
| ③ 补洞 | 剩余字节按三类处理：`0xCC` 连续段 → `pad`；≥4 字节可打印 ASCII → `data`（`text-blob`）；≥4 字节全零 → `data`（`zero-blob`）；否则解一条指令，失败则 1 字节 `data` | 填充、内嵌字符串、对齐零区不会被误判成垃圾指令 |
| ④ 分区自检 | 断言 `sum(单元大小) == 段 raw size`，且相邻单元首尾相接 | 任何遗漏或重叠立即失败 |

最终 `.text` + `INIT` 被切成 **43,363 个字节单元**：

| 类型 | 数量 | 字节数 |
|---|---|---|
| `insn` 指令 | 42,528 | 约 152 KB |
| `pad` int3 填充 | 587 段 | 29,597 |
| `data` 内嵌数据 | 248 段 | 约 8 KB |

## 3. 标签体系

| 前缀 | 含义 | 数量 |
|---|---|---|
| `DriverEntry` | PE 入口 `0x46000` | 1 |
| `sub_<rva>` | unwind 记录登记过的函数入口 | 1,146 |
| `loc_<rva>` | 分支目标 / 其它指令起点 | 约 2,200 |
| `dat_<rva>` | 数据段里的被引用地址（含 `.data` BSS 尾部） | 520 |
| `iat_<slot>` | IAT 槽位（备份工具链使用；主力工具链直接用 `dat_` + 注释） | 82 |

每一个 `[rip + disp]` 与每一个分支目标都会被解析成绝对地址，再映射到标签。这就是为什么生成的汇编里几乎看不到裸数字位移：

```asm
00001654  f0ff0ded3c0300    lock dec dword ptr [rip + 0x33ced]     ; -> dat_35348
0000166c  ff15d6d90200      call qword ptr [rip + 0x2d9d6]        ; ntoskrnl!IofCompleteRequest
0000169a  e8f1090000        call loc_2090                          ; -> loc_2090
```

## 4. 清单文件怎么看

`out/listing/ACE-ADVT.txt`（3.1 MB，47,270 行）每行四列：

```
RVA      原始字节                      助记符/伪指令                          注释
00001010 e9c44a0700                     jmp 0x140075ad9
00001650 4883ec28                       sub rsp, 0x28
00001654 f0ff0ded3c0300                 lock dec dword [rel dat_35348]
00004600 48895c2408                     mov qword [rsp + 8], rbx
```

- 注释列会把 IAT 引用解析成 `模块!函数名`，把 `dat_` 引用解析成字符串内容（如果是可打印串）
- `times N db 0cch` 表示 N 字节 int3 对齐填充（MSVC 的 `/Gy` 分函数布局会产生大量这种空隙）
- `DriverEntry` 的真实结构：建 `PDRIVER_OBJECT` 保存到全局、`sub_4602c` 做 CFG/`__security_init_cookie` 类初始化、然后 `call sub_1da0` 进入主初始化流程，返回值原样传回

## 5. 指令画像

| 助记符 | 条数 | 占比 |
|---|---|---|
| `mov` | 13,421 | 31.56% |
| `add` | 2,729 | 6.42% |
| `xor` | 2,687 | 6.32% |
| `call` | 2,374 | 5.58% |
| `lea` | 2,355 | 5.54% |
| `test` | 2,243 | 5.27% |
| `cmp` / `je` / `jne` | 1,556 / 1,550 / 1,340 | 10.45% |
| `pop` / `jmp` / `movzx` | 1,016 / 984 / 925 | 6.87% |
| `sub` / `ret` / `or` | 893 / 893 / 758 | 5.98% |
| `rol` / `push` / `shr` | 724 / 670 / 635 | 4.77% |

`rol` 出现 724 次（1.7%）明显高于普通编译器输出（通常 <0.2%），配合 `.tvm0` 里大量 `xor`/`rol`/`add` 组合，是混淆器常见的哈希与校验循环特征。

## 6. 函数体量分布

| 区间 | 函数数 |
|---|---|
| < 64 B | 515 |
| 64 – 255 B | 388 |
| 256 – 1023 B | 214 |
| 1 – 4 KB | 21 |
| ≥ 4 KB | 8 |

平均 794 字节。最大的一条是 `.tvm0` 的合成记录（覆盖整段 0x9BD58 字节），其次才是 `.text` 里的真实大函数。515 个小于 64 字节的函数多为 IAT thunk、`KeBugCheckEx` 包装和 CFG 校验存根。

## 7. 已知局限

1. **未被引用的叶子函数**：没有 unwind 记录、也没有被任何分支指向的代码，会落进"补洞"路径，可能被切成 `data` 或出现错位解码。这类区域集中在 `0x560..0x580`、`0xF560..` 附近的少数内嵌数据块里（ASCII 岛屿规则已吃掉大部分）。
2. **`.tvm0` 内的 111 个函数**：只登记了边界，未做语义反汇编（该段是 TVM 字节码/混淆原生码混合体，见 docs/03）。
3. **间接跳转**：`jmp rax` 类目标无法静态确定，跳转表未展开。
