# 10 · aux 家族 22 条命令逐条语义

`docs/09` 把 aux 家族（`0x623782AB` + k）的站点定位了。本文逐条追踪每个站点后的处理体，给出**每条命令在做什么**。

## 0. 结论

**aux 家族 = 一批"缓冲区混合/哈希"原语**。22 条命令的形态完全一致：

```
参数:  rsi = 缓冲区指针, r8d = 长度（0 长度直接跳空）
循环:  逐字节读取 [rsi + i]
混合:  每条命令一套不同的 移位/旋转/掩码/乘法常数
```

配合 `.rdata` 里的 **SHA-256 初始向量与轮常数**（`6A09E667` ×5、`BB67AE85` ×4、`428A2F98`…）以及 `0x2F380` 的 **256 字节置换表（S-box）**，这批命令属于驱动的**完整性/哈希子系统**：用户态让驱动对指定内存区间做哈希，结果回传后由服务端比对。

唯一的例外是 **k=5**：它不碰缓冲区，直接写回包头。

## 3. 哈希子系统的旁证

| 证据 | 位置 | 说明 |
|---|---|---|
| SHA-256 初始向量 | 全镜像 5 处 `6A09E667`、4 处 `BB67AE85`、4 处 `3C6EF372`、4 处 `A54FF53A` | 多份 IV（SHA-224/256 各一套） |
| SHA-256 轮常数 | `428A2F98`、`71374491`、`B5C0FBCF`、`E9B5DBA5`、`3956C25B` … | 完整 K 表 |
| 256 字节置换表 | `.rdata 0x2F380` | 0..255 的一个排列，S-box/P-box |
| 字符串 | `.rdata 0x306E0` = `SHA224`、`0x306E8` = `SHA256` | 算法名（给 `MmGetSystemRoutineAddress` 或内部选择用） |

### 3.1 修正：aux 不是 SHA-256 轮函数（实测否证）

用 `tools/sha_match.py` 把每条命令实际使用的移位量抽出来，与 FIPS 180-4 的四个模式对照：

| 命令 | 实测移位量 | 与 SHA-256 模式的交集 |
|---|---|---|
| k=2 | 1, 2, 4 | 1/3（只有 `2` 命中 Σ0） |
| k=4 | 1, 2, 4 | 1/3 |
| k=9 | 1, 2, 4 | 1/3 |
| k=30 | 1, 2, 4, 6 | 1/3 |
| 其余 | 全部落在 1/2/4/5/6/8 | ≤1/3 |

SHA-256 的 Σ0 需要 `22,13,2`、Σ1 需要 `25,11,6`、σ0 需要 `18,7,3`、σ1 需要 `19,17,10`。**22 条命令里没有任何一条同时出现这三元组**，全部集中在 1–8 的字节级移位。

所以更准确的结论是：

- **aux 家族 = 字节级混合/变换原语**（每条一套乘法常数 0x33/0xB7/0x1A/0x22/-3 与掩码 0x40/0x55/2/7），作用是对缓冲区做**可逆变换**（很可能是请求载荷的校验/混淆层），**不是** SHA-256 的轮函数；
- SHA-256/SHA-224 实现**独立存在于镜像中**（IV、K 表、S-box 都在），服务于文件/内存完整性校验，与 aux 命令是两套东西。


## 4. k=5 的特殊性（对绕过最有价值）

```
0x63B61  mov eax, 0x3FFFFF44 ; not → 0xC00000BB
0x63B8E  test rdx,rdx ; je
0x63B38  mov dword [rdx],   0x01343BEB
0x63B3E  mov dword [rdx+4], 0x30
0x63B11  mov dword [rdx+8], r8d
0x63B15  mov dword [rdx+0xC], r10d
```

- 不读输入缓冲区，只写 16 字节回包（后面 32 字节零填充 → 总 48）；
- `r8d` / `r10d` 是两个状态值（来自调用者）；
- 返回 `0xC00000BB` 当输出指针为空。

这是**握手/探针**命令：客户端用它确认"通道活着 + 版本/状态"，也是伪造回包时最容易冒充的一条。

## 5. 对绕过方案的影响

| 场景 | 变化 |
|---|---|
| 伪造回包 | 只需处理两条：**k=5**（探针，回 `{0x01343BEB,0x30,0,0}`）和**哈希类命令**（回一个"看起来对"的 32 字节摘要） |
| 对抗完整性检查 | 哈希结果由驱动算、用户态比对 → **截断点在回包**，不需要改驱动内部；返回预先算好的正确摘要即可 |
| 反混淆成本 | aux 命令体虽然平坦化，但**语义同质**（都是字节混合），逐个精确还原的边际收益低；掌握"它是哈希"这一点就够做决策 |

## 6. 遗留（明确）

| 项 | 状态 |
|---|---|
| 每条命令对应 SHA-256 的哪一步（σ0/σ1/Σ0/Σ1/轮加） | 未定：需要按"常数 + 移位组合"与 FIPS 180-4 对照逐条匹配（可做，约半天） |
| 哈希的输入来源（哪个内存区间） | 未定：由调用者（`0x63C29` 28.6 KB 主函数）传入 `rsi/r8d`，需要跟调用点 |
| k=25/29/30 的具体常数 | 中置信，需继续跟 |

> 本文所有"高置信"条目都有首段真实指令作为证据（RVA 已列），"中置信"条目已明确标注，不作结论使用。
